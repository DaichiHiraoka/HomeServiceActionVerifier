# 「触る・持ち上げる」が棒人間と物の位置だけでわかる理由と、コードのどこが担っているか

## 前提：システムが持っている情報は2つの表だけ

| 表 | 中身 | 作るコード |
| --- | --- | --- |
| 骨格の表 | 1コマごとの体33点の画面上の位置。手首は左=15番・右=16番、肩=11/12番、腰=23/24番、足首=27/28番 | `src/.../pose.py` の `extract_pose()`（列名 `lm15_x` などで保存） |
| 物の表 | 1コマごとの物の中心位置(cx, cy)・大きさ(w, h)・見えているか | `src/.../tracking.py` の `interpolate_objects()`（人が要所に付けた印を `_interpolate_one_object()` が直線的に埋める） |

この2つの表は同じ「コマ番号(frame)」を持っているので、**同じ瞬間の「手首の位置」と「物の位置」を突き合わせられる**。動作がわかる理由はすべてこの突き合わせに帰着する。

## 一つだけ正直な注意：「いつ触ったか」は今は人間が教えている

現在の実装では、「この物にこのコマからこのコマまで接触した」という**接触区間そのものは人手の印**（annotation.json の `contacts`）であり、`windows.py` の `build_contact_windows()` がその区間の前後を切り出す（設定 `contact_source: gt`）。

システムが自力で判定しているのは「**触り方・持ち方・その後の流れが普通か不自然か**」の部分である。ただし後述の「手首と物の距離」はしきい値を切るだけで接触の自動検出にも転用できる形で実装してあり、将来の拡張点として設計されている（`config.py` の `contact_source` が切り替え口）。

## 動作ごとの原理とコード対応

### 1.「触る」がわかる理由

**原理**：触る＝手首の点と物の中心が画面上でほぼ同じ場所に来ること。左右どちらの手で触ってもいいように、左手首・右手首それぞれと物の距離を計算し、**近い方**を採用する。体格やカメラ距離で「近い」の基準がぶれないよう、距離は**肩幅で割って**正規化する。

**コード**：`src/.../features/relation_feats.py` の `compute_relation_features()`

```python
left  = √((lm15_x − cx)² + (lm15_y − cy)²)   # 左手首と物の距離
right = √((lm16_x − cx)² + (lm16_y − cy)²)   # 右手首と物の距離
wrist_dist = min(left, right) / scale          # 近い方を肩幅で正規化
```

肩幅（ものさし）は `features/common.py` の `shoulder_width()`（11番と12番の距離の中央値）。生成される特徴は `REL__wrist_obj_dist_min/mean/last` など。

### 2.「持ち上げる・持っている」がわかる理由

**原理**：一瞬近づいただけ（横を通った、指差した）と、持っているの違いは**近い状態が続くかどうか**。「距離がしきい値（肩幅の8%）より小さいコマ数 ÷ コマ速度 ＝ 保持していた秒数」を数える。さらに、持ち上げたなら**物が動き出す**。「物が最初の位置からどれだけ離れたか」「物の移動速度」が、手が近い時間帯と同期して増えることが持ち上げの証拠になる。手だけ動いて物が動かなければ「触ったが持ち上げていない」。

**コード**：
- 保持時間：`relation_feats.py` 内 `REL__hold_duration_s = (wrist_dist < config.hold_dist_threshold) の数 / fps`。しきい値は `config.py` の `FeaturesConfig.hold_dist_threshold = 0.08`（試し撮りで較正する値）
- 近づく/離れる速さ：同ファイル `wrist_obj_dist_delta`（距離の1コマ差分。急接近＝マイナスに振れる）
- 物が動いた事実：`features/object_feats.py` の `compute_object_features()` — `OBJ__disp_from_initial_*`（最初の位置からの距離）と `OBJ__speed_*`（移動速度）

### 3.「拾うためにしゃがむ・かがむ」がわかる理由

**原理**：低い場所の物を取るとき、腰の点が足首の点に近づき（座り込み）、肩が腰より前に出る（前かがみ）。手首の点の高さも下がる。接触の瞬間の前後0.5秒だけを見れば、その接触が「立ったまま」か「しゃがみ込んで」かが数字で区別できる。

**コード**：`features/skeleton_feats.py` の `compute_skeleton_point_features()` — `SKEL_POINT__wrist_height`（手首の高さ）、`SKEL_POINT__hip_ankle_gap`（腰と足首の縦の差＝しゃがみ度。しゃがむと小さくなる）、`SKEL_POINT__trunk_lean`（肩と腰の横ずれ＝前かがみ度）。切り出しは接触開始コマ±0.5秒。

### 4.「体に引き寄せて隠す」がわかる理由

**原理**：隠す動きの本質は、物が**手先ではなく胴体の近く**に長時間とどまること。胴体の中心（肩2点＋腰2点の平均）と物の距離が、拾った後に小さいまま推移する。

**コード**：胴体中心は `features/common.py` の `trunk_center()`、距離は `relation_feats.py` の `REL__trunk_obj_dist_*`。

### 5.「返した／持ち去ろうとしている」がわかる理由

**原理**：返却＝物の最終位置が初期位置とほぼ一致する（距離ゼロに戻る）。持ち去り＝初期位置からの距離が増え続け、しかも物と体が**出口の方向**へ進む。出口の向きは部屋の設定（作業領域の中心→出口の点）から決まるベクトルで、移動をそのベクトルに射影した速さがプラスなら「出口へ向かっている」。触った後に体が作業領域内へ戻ったかの割合も計算する。

**コード**：`features/context_feats.py` の `compute_context_features()` — `CTX__obj_return_dist`（最終位置と初期位置の距離＝返却の代理指標）、`CTX__obj_exit_velocity_mean` / `CTX__trunk_exit_velocity_mean`（出口方向成分の速度）、`CTX__post_work_area_return_rate`（接触後に作業領域ポリゴン内にいた割合。内外判定は `matplotlib.path`）。作業領域と出口は annotation.json の `work_area` / `exit_point`。

## なぜ「点の位置」だけでここまで言えるのか（まとめ）

人の動作は関節の位置関係の時間変化として物理的に表れる。「触る」は手首と物の座標の一致、「持つ」はその一致の持続＋物の移動、「しゃがむ」は腰と足首の接近、「隠す」は物と胴体の接近の持続、「持ち去る」は物の座標の一方向への移動。**どれも「誰が」「どんな見た目で」という情報を一切必要としない**。だから顔や服装を捨てても動作は残る。これがこの研究のプライバシー設計が成り立つ理由そのものである。

## この方法の弱点（コードの限界と対応箇所）

- **奥行きがわからない**：画面は2次元なので、手前の手と奥の物が「画面上では重なって」見えることがある。距離はあくまで画面上の距離である。→ カメラ位置の工夫（試し撮りで決める）と、誤分類分析で影響を確認する
- **隠れると見えない**：体の陰に入った物は追えない。物の表には `visible` 列があり、見えない区間は距離計算から除外される（`relation_feats.py` は `visible` が真のコマだけ突き合わせる）。「見えなくなったこと」自体も `OBJ__visible_rate` や `CTX__post_obj_visible_rate` として特徴になっており、**不自然に消えたこと自体が手がかり**として使われる
- **骨格の読み取り失敗**：しゃがみや後ろ向きで点が取れないコマは `pose.py` の `interpolate_skeleton_gaps()` が短い欠損（15コマまで）だけ前後から埋め、長い欠損は欠損のまま扱う（無理に作らない）
