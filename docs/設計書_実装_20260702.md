# 実装設計書：骨格・物体位置・文脈情報による不自然物品操作系列の分類システム

対象読者：本リポジトリで実装を行う本人（＋コーディングエージェント）。
準拠文書：`論文_プロト_v2.md` `卒業研究_実験計画.md` `docs/レビュー_技術スタック・実験計画・実現可能性_20260702.md`（以下「レビュー」）。

## 0. 設計原則

1. **オフライン処理のみ**。録画済み動画を入力とし、リアルタイム性は要求しない（Time-to-detection は録画への逐次適用で算出）。
2. **特徴量は骨格座標と物体bboxからの自動計算のみ**（レビューR1対策）。人手アノテーションは「物体bboxキーフレーム」「作業領域」「接触区間の正解」「系列ラベル」に限定し、「返却した/しない」等の意味ラベルを入力特徴に使うことを禁止する。
3. **実験条件A–Fは特徴量グループの選択で表現する**。モデルコードを条件ごとに分岐させない。
4. **全ステージがファイル入出力で分離**され、単独で再実行・検査できる（動画→骨格→トラック→特徴→データセット→学習評価）。
5. 乱数シード・設定・コード版数を結果ディレクトリに保存し、全実験を再現可能にする。

## 1. パイプライン全体像

```
[録画 mp4] ─ pose ─→ [skeleton.parquet]
[録画 mp4] ─ annotate(GUI/手動JSON) ─→ [annotation.json]（bboxキーフレーム・作業領域・接触区間GT・ラベル）
[annotation.json] ─ track ─→ [objects.parquet]（フレーム毎bbox補間）
[skeleton + objects] ─ features ─→ [features.parquet]（ウィンドウ毎特徴ベクトル）
[features] ─ dataset ─→ [dataset.parquet]（条件・文脈長で選択済みのX,y,メタ）
[dataset] ─ train/eval ─→ [outputs/experiments/<exp_id>/...]（指標・混同行列・スコア曲線）
```

## 3. データ仕様

### 3.1 命名とID

- `seq_id = {session}_{actor}_{scenario}_{rep:02d}`　例：`s01_a1_normal-repair_03`
- `actor`（演者ID）は LOPO の group キー。`scenario` はシナリオ台本ID。

### 3.2 skeleton.parquet（フレーム×ワイド形式）

| 列 | 型 | 説明 |
| --- | --- | --- |
| frame | int | 0始まり |
| time_s | float | frame / fps |
| lm{00..32}_x, _y | float | 画像正規化座標 [0,1]。MediaPipe Pose 33点 |
| lm{00..32}_z | float | MediaPipe相対深度（参考値扱い） |
| lm{00..32}_vis | float | visibility |
| pose_ok | bool | 推定成功フラグ |

欠損方針：`pose_ok=False` のフレームは前後線形補間（連続欠損 > `max_gap_frames`（既定15）は補間せずNaN維持）。**系列ごとの欠損率を meta に記録し、論文のデータ品質報告に使う。**

### 3.3 annotation.json（1系列1ファイル・人手作成）

```json
{
  "seq_id": "s01_a1_unnat-carry_01",
  "video": "data/raw/s01/s01_a1_unnat-carry_01.mp4",
  "fps": 30.0,
  "label": "unnatural",                    // "normal" | "unnatural"
  "scenario": "unnat-carry",
  "actor": "a1",
  "work_area": [[0.55,0.30],[0.95,0.30],[0.95,0.85],[0.55,0.85]],  // 正規化座標ポリゴン
  "exit_point": [0.05, 0.50],              // 出口の代表点（特徴導出用の幾何情報）
  "objects": [
    {
      "object_id": "wallet",
      "role": "non_task",                  // "task" | "non_task"（統計・分析用。特徴には使わない）
      "keyframes": [
        {"frame": 0,   "bbox": [0.42,0.60,0.06,0.05]},   // [cx,cy,w,h] 正規化
        {"frame": 210, "bbox": [0.41,0.61,0.06,0.05]},
        {"frame": 260, "bbox": null}                      // null = 遮蔽/画面外
      ]
    }
  ],
  "contacts": [
    {"object_id": "wallet", "start_frame": 215, "end_frame": 400}   // 接触区間GT
  ]
}
```

制約（`annotation.py` の validate で強制）：
- `label` 定義に関わる意味情報（返却有無・復帰有無など）のフィールドを**持たない**。これらは特徴量として自動導出する（設計原則2）。
- bboxキーフレームは物体が静止している区間は疎で良い（補間前提）。移動中は0.5–1秒間隔。
- `role` は誤分類分析専用。`dataset.py` が特徴列に混入させないことをテストで保証する。

### 3.4 objects.parquet（tracking.py の出力）

frame, object_id, cx, cy, w, h, visible(bool)。キーフレーム間は線形補間、`bbox:null` 区間は visible=False。

### 3.5 features.parquet

1行 = 1ウィンドウ。列 = `seq_id, actor, scenario, label, contact_id, ctx_sec, t_end_rel`（早期検知用：接触開始からの経過秒）＋ 特徴列。特徴列名は `"{group}__{name}"` 形式（例 `REL__wrist_obj_dist_min`）。条件A–Fの選択は列名プレフィックスで行う。

## 4. 特徴量設計

ウィンドウ定義（`windows.py`）：接触イベント（GT区間、将来は自動検出に置換可能なようにインターフェース分離）を基準に、`[start - ctx, end + ctx]` を切り出す。早期検知用には `t_end` を接触開始後 0/1/3/5 秒…と打ち切った「打ち切りウィンドウ」を同じ関数で生成する。

| グループ | 主な特徴（各 min/max/mean/std/last 等で集約） | 条件 |
| --- | --- | --- |
| SKEL_POINT | 接触時点±0.5sの関節角度（肘・膝・体幹前傾）、手先高さ、しゃがみ度 | A |
| SKEL_SEQ | 体幹速度・移動量、姿勢遷移回数、しゃがみ↔立位の遷移、停止時間率 | B,D,E,F |
| OBJ | 物体変位（初期位置比）、速度、visible率、bbox面積変化 | C,D,E,F |
| REL | 手首-物体中心距離（左右min）、距離の時間微分、保持時間（距離<θの継続長）、物体-体幹中心距離（「身体側に隠す」の代理） | C,D,E,F |
| CTX | ①接触終了後の体幹と作業領域重心の距離推移、②物体最終位置と初期位置の距離（=返却の自動導出）、③物体/体幹の出口方向成分速度、④接触終了後に作業領域内滞在へ戻った割合 | E,F |
| CROP | 物体bboxを1.5倍に拡張した局所クロップ（上限 128×128px 相当・論文に明記）の HOG または軽量CNN埋め込みの系列集約 | F |

条件定義（`configs/conditions.yaml`）：

```yaml
A: {groups: [SKEL_POINT]}
B: {groups: [SKEL_SEQ]}
C: {groups: [OBJ, REL]}
D: {groups: [SKEL_SEQ, OBJ, REL]}
E: {groups: [SKEL_SEQ, OBJ, REL, CTX]}
F: {groups: [SKEL_SEQ, OBJ, REL, CTX, CROP]}
```

座標系の注意：全特徴は正規化画像座標で計算し、距離系特徴は肩幅（lm11-lm12距離の系列中央値）で正規化して体格・カメラ距離の影響を低減する。

## 5. モデル・学習

`models.py`：`make_model(name, seed) -> sklearn Pipeline`

- `logreg`：StandardScaler + LogisticRegression（解釈性ベースライン）
- `rf`：RandomForest（主力候補）
- `lgbm`：LightGBM（主力候補）

ハイパラは固定 or 小さなグリッド（内側CVは行わない。n が小さいため既定値近傍で固定し、その旨を論文に書く）。クラス重みは balanced。

## 6. 評価（evaluate.py）

- **LOPO**：`GroupKFold` 相当（group=actor）。fold毎に fit/predict。
- 指標：accuracy, precision, recall(unnatural), F1(unnatural), FPR, ROC-AUC, PR-AUC, confusion matrix。
- **不確実性**：①シード5本の平均±SD、②系列単位 bootstrap（B=1000）による F1 の95%CI、③条件間比較は同一foldの予測を用いた McNemar 検定。
- 出力：`outputs/experiments/<exp_id>/metrics.json`, `per_fold.csv`, `predictions.csv`（seq_id毎のスコア。誤分類分析の元データ）, `config_snapshot.yaml`, `git_sha.txt`。

## 7. 早期検知（early.py）

1. 学習済みモデル（文脈長5s条件）を、打ち切りウィンドウ列 `t_end_rel ∈ {-1, 0, 1, 2, 3, 5, 8}` 秒に適用しスコア曲線 `score(t)` を得る。
2. 警報閾値 θ は LOPO の学習fold内で「FPR≤0.20 を満たす最小閾値」として決定（テストfoldに漏らさない）。
3. 指標：Time-to-detection（接触開始→score≥θ の初到達時刻）、作業領域離脱前検知率、各打ち切り時点での recall/FPR。
4. 出力：`early_curves.parquet`、系列別スコア曲線図（論文図の素材）。

## 8. CLI（cli.py / `python -m home_service_action_verifier`）

```
hsav pose      --video <mp4|dir> [--out data/interim/]        # 骨格抽出
hsav track     --annotation <json|dir>                        # bbox補間
hsav features  --seq <seq_id|all> --ctx 1 3 5 10              # 特徴量生成
hsav dataset   --condition A..F --ctx 5                       # X,y構築
hsav train     --condition E --ctx 5 --model lgbm --seed 0
hsav evaluate  --exp <exp_id>                                 # 指標・図
hsav grid      --config configs/default.yaml                  # 条件×文脈長×シード一括
hsav early     --exp <exp_id>                                 # 早期検知評価
hsav qc        --seq all                                      # 欠損率・アノテ検証レポート
```

`grid` が主実験の入口：conditions × ctx {瞬間,1,3,5,10} × seeds {0..4} × models {rf,lgbm} を回し、集計表 `summary.csv` を出す。

## 9. 設定（configs/default.yaml 抜粋）

```yaml
pose:
  model_complexity: 1
  min_detection_confidence: 0.5
  max_gap_frames: 15
windows:
  ctx_seconds: [0, 1, 3, 5, 10]
  contact_source: gt        # gt | auto（将来拡張）
features:
  hold_dist_threshold: 0.08  # 正規化距離。パイロットで較正
  crop_scale: 1.5
  crop_max_px: 128
eval:
  seeds: [0, 1, 2, 3, 4]
  bootstrap_n: 1000
  target_fpr: 0.20
```

## 10. テスト計画（tests/）

| テスト | 内容 |
| --- | --- |
| test_schemas | annotation.json の validate（必須キー・禁止キー（意味ラベル系）の検出） |
| test_tracking | キーフレーム2点→補間値の厳密一致、null区間の visible=False |
| test_features_synthetic | 合成データで検証：物体を初期位置に戻した系列→ `CTX__obj_return_dist≈0`、出口へ移動→出口方向速度が正、等 |
| test_no_leakage | dataset に `role`・`label` 由来列が特徴として混入しないこと／早期検知の θ 決定がテストfoldを参照しないこと |
| test_windows | 打ち切りウィンドウが t_end を超えるフレームを含まないこと |
| test_eval | 完全予測でF1=1、群分割で同一actorがtrain/testに跨らないこと |

合成フィクスチャ（等速直線運動の骨格・bbox）を fixtures に置き、実動画なしで全パイプラインをCIで回せるようにする。

## 11. 実装順序（レビューの工数見積りに対応）

1. **W1**：schemas / config / video_io / pose → 手持ち動画1本で skeleton.parquet が出る
2. **W2**：annotation / tracking / windows → 自作アノテ1系列で objects.parquet
3. **W3**：features（SKEL_SEQ, OBJ, REL, CTX）/ dataset / models / evaluate → ダミー2系列で train まで貫通（**ここまでが7月中の最優先マイルストーン**）
4. **W4**：qc / grid / report、SKEL_POINT・CROP、テスト整備
5. パイロット撮影 → `hold_dist_threshold`・カメラ位置の較正、シナリオ台本凍結
6. 本収集後：grid 実行 → early → 誤分類分析

## 12. コーディング規約・その他

- Python 3.12 / uv。フォーマット・lint は ruff。型ヒント必須（schemas は dataclass or TypedDict）。
- 例外方針：データ不備は `qc` で検出しfail-fast。パイプライン中の黙殺的スキップ禁止（スキップ時は必ずログ＋集計）。
- ログ：標準 logging。各CLIは処理系列数・欠損率・所要時間を INFO で出す。
- 生画像の永続化は raw/ のみ。interim/processed には骨格・bbox・クロップ（上限サイズ）以外の画像を書かない（プライバシー設計の実装的裏付けとして論文に記載できる）。
