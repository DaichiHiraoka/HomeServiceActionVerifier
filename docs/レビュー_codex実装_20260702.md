# コードレビュー：Codex実装（src/・tests/）

対象：`src/home_service_action_verifier/`（23ファイル・約1,860行）、`tests/`（9テスト、全パス確認済み）。
基準：`docs/設計書_実装_20260702.md`。

## 総評

設計書への追従度は高い（8割方実装済み）。ステージ分離・特徴グループのプレフィックス選択・禁止キー検証・LOPO・打ち切りウィンドウ対応の `windows.py` など、骨格は設計通りで品質も良い。**ただし研究の主張に直結する欠落が3つある**：早期検知パイプラインの未配線、CROP特徴のスタブ化（条件Fが無意味）、物体トラックの時間範囲不足。これらを直すまで「実装完了」とは言えない。

## P1：研究の主張を壊す問題（必修）

### P1-1. 早期検知パイプラインが存在しない（設計§7）

`windows.build_contact_windows` は `truncate_seconds` を受けられるが、**呼び出し側が存在しない**。`cmd_features` は打ち切りなしで呼び、`cmd_early` は `early_curves.parquet` を読むだけで、**それを生成するコードがどこにもない**。さらに `choose_threshold_for_fpr`（学習fold内での閾値決定）はどこからも呼ばれず、CLI `early` は `--threshold 0.5` の手指定。このままでは Time-to-detection 実験（実験計画§7）が実行不能。

必要な実装：
- `hsav early-curves --exp <exp_id>`（または train に統合）：LOPO の各foldで、学習foldで fit したモデルを、テストfold系列の打ち切りウィンドウ（`t_end_rel ∈ {-1,0,1,2,3,5,8}` 等）に適用し `early_curves.parquet` を出力
- 閾値は `choose_threshold_for_fpr` を**学習foldのスコア**に適用してfold毎に決定（現状の手指定はリーク以前に恣意的）
- `summarize_score_curves` の `time_to_detection` の単位を明示（現状 t_end_rel をそのまま返す＝秒。OK だがdocstringなし）

### P1-2. CROP特徴がプレースホルダで、条件Fが検証不能

`crop_feats.py` は bbox 面積と可視率のみ（`crop_area_mean` 等）で、**局所クロップ画像を一切読んでいない**。これでは F は「E＋bboxサイズ」でしかなく、論文の「物体周辺画像が性能向上に寄与するか」（比較条件F）の検証にならない。選択肢は2つ、どちらかに今決める：
1. 設計通り HOG（skimage）or 軽量CNN埋め込みを実装する（動画フレーク読み込み＋クロップ切り出しが必要＝`features` ステージに video 入力を追加）
2. 卒研スコープから条件Fを外し、論文プロトv2の比較表からも落とす

中途半端に現状のFを回すと「F≈E」という無意味な結果が出て解釈を誤る。

### P1-3. 物体トラックがウィンドウ範囲をカバーしない

`tracking._interpolate_one_object` は**最終キーフレームで打ち切る**。`interpolate_objects` 冒頭で contacts を含む `max_frame` を計算しているのに**未使用**（デッドコード＝実装しかけの痕跡）。最終キーフレーム以降のフレームに行が無いため、接触後文脈（CTX の `post_*`、OBJ、REL）が**アノテータの最終キーフレーム位置次第で欠損**する。返却・持ち去りの判定は接触後こそが本体なので致命的。

修正：最終キーフレームから `max_frame` まで bbox を保持（静止仮定）または `visible=False` で埋める。仕様としてどちらかを明記。加えて境界バグ：`bbox0` 有効・`bbox1` null の区間で、**有効な bbox を持つキーフレーム自身（frame=start）まで invisible になる**。frame==start は bbox0 を使うべき。

## P2：今直さないと後で事故る問題

- **P2-1. `build_dataset` が `t_end_rel` をフィルタしない。** 現状は inf のみなので無害だが、P1-1 で打ち切りウィンドウが features.parquet に入った瞬間、**打ち切り行が学習データに混入する**。`t_end_rel == inf` のフィルタを今入れておく（テストも追加）。
- **P2-2. `pose.py` が config を無視。** `extract_pose` は `model_complexity=1, min_detection_confidence=0.5` をハードコードし、`PoseConfig` の値が渡っていない（`max_gap_frames` のみ使用）。config_snapshot に記録される値と実挙動が乖離し、再現性の記録が嘘になる。
- **P2-3. bootstrap・シード集計が未配線。** `bootstrap_f1_ci` は実装済みだが CLI/grid から呼ばれず、`eval.bootstrap_n` 設定も未使用。レビューR3（統計的堅牢性）の対応が絵に描いた餅になっている。`grid` の summary にシード平均±SD と代表条件の95%CIを出すところまで繋ぐ。
- **P2-4. 骨格補間が「長い欠損の部分埋め」をする。** pandas `interpolate(limit=15)` は30フレーム欠損でも先頭15フレームを埋める。設計は「gap>15は補間しない」。gap長を測って全欠損を維持する実装に（または仕様側をこの挙動に合わせて明文化）。
- **P2-5. qc が薄い。** annotation の fps と動画実 fps の一致、`seq_id` と動画ファイル名の一致、skeleton/objects の存在、contacts がトラック範囲内か、をチェックすべき。P1-3 型の事故は qc で捕まえられる。

## P3：軽微（気づいた点）

- `early.choose_threshold_for_fpr` が O(n²)（候補ごとに compute_metrics 全計算）。データ小なので動くが、`sklearn.metrics.roc_curve` で一発。`"normal"` の文字列直書きも `NEG_LABEL` に。
- CTX の作業領域内判定がポリゴンでなく**外接矩形**（min/max）。矩形運用なら実害なしだが、設計とズレるので docstring に明記 or `matplotlib.path.Path.contains_points` に。
- `SKEL_POINT` の `crouch = (ankle_y - hip_y)/scale` は**立位で大・しゃがみで小**（画像y軸は下向き）。特徴としては機能するが名前が逆。誤分類分析時に混乱するのでリネーム推奨。
- `run_grid` に `--models` がCLIから渡せない／dataset をシードループ内で再構築（無駄だが無害）。
- `report.plot_score_curve`・`build_empty_skeleton_for_video` はどこからも未使用。
- テスト補強：P1修正に対応する回帰テスト（トラック範囲、t_end_rel フィルタ、fold内閾値のリーク無し）を必ず足す。現状の `test_no_leakage` は列選択のみで、時間方向・fold方向のリークは未カバー。

## 良かった点

- 禁止キー検証が**ネスト再帰**で実装されており、設計意図（R1: 意味ラベル混入禁止）を正しく汲んでいる
- 特徴量は全グループ計算→データセット段でプレフィックス選択、という設計の分離が正確
- `evaluate_lopo` の per-fold 出力・predictions.csv・LGBM遅延import・Imputer入りPipelineなど実務的な作りが丁寧
- 打ち切りウィンドウの `end_frame` クランプ（`min(full_end, max(full_start, ...))`）とそのテストは正しい

## 残る軽微な指摘（次回ついでに）

1. **`cli.py` `cmd_early` のログ**：`LOG.info(... "threshold=%.3f" ..., args.threshold, ...)` は `--threshold` 省略時（既定 None）に logging エラーを吐く（コマンド自体は成功する）。`%s` に変更。
2. **`early.py` の特徴列選択**：`[c for c in early_fold.columns if "__" in c]` は `is_feature_column` / `feature_columns_for_groups` を使うべき。現状は無害だが、将来 `__` を含むメタ列が増えると静かに混入する。
3. **閾値較正の限界（論文用メモ）**：閾値は学習foldの**訓練スコア**から決めるため、RFの訓練スコアは過分離しており実テストFPRは目標(0.20)からずれうる。リークではないので設計として妥当だが、論文では「学習fold内で決めた閾値のテストfold実測FPR」を併記すること。改善するならRFの`oob_decision_function_`か内側CVスコアで閾値決定。
4. **アノテーション規約の明文化**：トラック延長は「最終キーフレームのbboxを静止と仮定して保持」。持ち去りで物体が画面外に消える系列は**最後のキーフレームを `bbox: null` で終える**運用にしないと「物体がその場に残り続ける」ことになる。この規約を README か設計書に一行追記。

## 結論

前回のP1/P2/P3指摘は**すべて解消**。実装は撮影データ受け入れ可能な状態。次のボトルネックはコードでなく、パイロット撮影（カメラ位置・`hold_dist_threshold` 較正）とシナリオ台本の凍結。
